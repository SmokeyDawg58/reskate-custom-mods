Solo Throwdown exit and 1-Up marker restrictions (2026-10-09)
===========================================================

Candidate changes
-----------------
Stock one-player Throwdowns preserve the original LeaveInProgressRequested
message while additionally requesting destruction of the otherwise empty
native event. Replacing Leave with ForceDestroy in the previous candidate
removed the normal participant confirmation needed by the client.

Confirmed server removal or native EnterEnd releases the owning SDK flags.
For a confirmed solo completion, the adapter also resets the native client's
InActivity and MPActivityIdleState values once, provided the player and
captured activity group still match. A new queue, other player, old activity,
guest match, multiplayer event or world teardown cannot inherit this reset.
LeaveInProgress alone is a request and does not prove completion.

During active 1-Up participation, the native marker data model disables
placing and returning to markers. Both native expression runners reject
the verified Set, Setting, Undo and Return action graphs at entry. Hash and
full resource layout must match; resumed and unrelated graphs still run.
Trainer marker commands, teleport commands and automatic bail return also
respect the active match. Internal 1-Up spawn positioning remains available.
Restrictions end when the match ends or the local player leaves it.

The native local-player activity predicate and UIPlayerInfo recognize an
active 1-Up participant after the temporary flag queue is gone. This lets
the original activity pause menu supply its Quit Match confirmation.
Confirmed Quit Match requests end the owned 1-Up match. The owned waiting
HUD action also reads QUIT MATCH during play, and LEAVE before play.
