## Opening-menu crash and black debris follow-up

The first updated build crashed when opening Throwdowns, and the user reported black litter/debris. Its native dump (`../reskate-v2.0.3-crash/CrashDump_2026.10.10_15.13.48.419.mdmp`) was unwound using AMD64 PE unwind metadata rather than treating every code-looking stack word as a caller. The actual path is the native model read at game RVA `0x190e020`, followed by the typed CString copy at `0x3daa880`, then `ucrtbase!strlen` reading null. Ghidra's decompilation and the offline unwind evidence are saved in that investigation folder.

Custom native model creation and typed template copies initialize null inline CString fields with engine-owned empty strings, recursively through inline structures. Asset pointers, DataRefs and arrays retain their native semantics. Clearing a string uses the engine's string constructor instead of zero bytes; blank labels are initialized even when their visible text is already empty. This initial repair did not resolve the crash: subsequent first-chance capture established that a callback field was being read as text. No global string function or stock VM instruction is replaced.

The asset author previously included a complete BAM shared world shader depot in the picker bundles to support tutorial checkpoint meshes. That could register unrelated materials before their world texture dependencies were resident. It now emits a private depot containing exactly eight checkpoint material keys, keeps each selected block's native parameters unchanged, and rejects any attempt to include a shared world depot. The compiled pack still includes the native checkpoint meshes, textures and streaming chunks. The user confirmed that the black debris was fixed.

Corrected pack generation, serialization checks, isolated compilation (104 resources, 12 bundles, 10 TOCs), the Release build and all 72 runtime/launcher regression tests completed successfully. Evidence lives in `../reskate-v2.0.3-crash/`. The asset-author source changes are in the companion ReSkateStudio workspace; the runtime fix and embedded pack remain DLL changes.

## Picker model-path investigation

The next user-triggered crash, `CrashDump_2026.10.10_16.24.37.283.mdmp`, has the same unwound native typed-read/CString-copy/strlen stack. `menu-binding-layout.json` captures the entire relevant type tree and flattened model-field table. The first-chance read uses a ScrollViewModel key with field path `[1]` (Text), CString output type and `PrecalcOffset=2`. Its captured output handle selects index 30: the delegate at byte offset 208. Subtracting the key's offset gives an inherited scope at index 28, whereas the actual ScrollViewModel is at index 29. The real Text field is index 31, byte offset 216. An empty string at the real field cannot correct that wrong scope. `../verify_menu_binding_fault.py` independently checks the captured handles and offsets against the native metadata.

An attempted repair cloned the referenced RimeWidgetBlueprint/LogicPrefabBlueprint chain and set private `PrecalcOffset=-1` paths. The live retest still crashed. Its dump, `typed-picker-retest/CrashDump_2026.10.10_16.56.58.842.mdmp`, fails at native model construction RVA `0x1912670`: a supposed type pointer dereferences the ASCII bytes `UI/ReSka`. The upstream music constructor hook appears as a forwarding frame; the exception occurs in its original native call. The recursive cloning/path invalidation approach was removed. A `native-ui-imports` CLI command remains available for repeatable dependency inspection.
